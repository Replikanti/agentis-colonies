# LLM backend — full reference

Long-form documentation of the federation LLM wiring (moved from `CLAUDE.md`
2026-07 to keep the always-loaded context lean; `CLAUDE.md` §LLM backend keeps
the operative rules). This file is the authoritative deep dive: env knobs,
resolution order, and failure modes.

Federations default to **flat-cyborg** ([`Replikanti/flat-cyborg`](https://github.com/Replikanti/flat-cyborg)) — a PTY wrapper that drives the interactive Claude Code session, so `prompt()` bills against a **flat-rate** Claude subscription instead of the metered `claude -p` API (`usage = None`). Two wiring styles, both flat-cyborg:

- **Container federations** (`trading-binance`, `tribes-bench`, `research-foundry`) inject the **native** agentis-core backend `llm.backend = flat-cyborg` (requires agentis **>= v1.19.0** — pin `ARG AGENTIS_VERSION` accordingly in the federation's `Containerfile`) into the hermetic `.agentis/config` from their run/replay orchestrator, and bind-mount the host operator's `~/.claude` into the container at `/root/.claude:rw,z` (`:z` for SELinux/Fedora). Each orchestrator keeps a metered `claude` and/or `openai` path as an **opt-in fallback** via its `*_LLM_BACKEND` env knob (e.g. `REPLAY_LLM_BACKEND`, `STAGE3_LLM_BACKEND`, `RESEARCH_LLM_BACKEND`). `research-foundry` additionally routes per confidence tier via `llm.tier.<tier>.model` (haiku for dormant/shadow, sonnet for propose/review-gated/autonomous, opus for the terminal-writer agents).
- **Host-run federations** (`dev-apprenticeship`, `dark-factory`) set `llm.backend = claude` + `llm.command = tools/flat-cyborg-claude.sh` (the wrapper script) in `.agentis/config` via `install.sh` / the run scripts, so the on-host `agentis daemon` shells out to flat-cyborg.

**Workload-based model routing (host-run).** The two host-run claude-invocation sites pass an explicit `claude --model`, splitting by how demanding the work is: every agent's `prompt()` reasoning goes through `tools/flat-cyborg-claude.sh` on **Sonnet 5** (`--model sonnet`, the lighter/faster tier — override with `CLAUDE_REASONING_MODEL`), while the heaviest workload — actual multi-file code generation in `tools/code-edit-in-checkout.sh` — runs on **Opus 4.8** (`--model opus`, override with `CODE_EDIT_MODEL`). Both default in-script (no env-passthrough dependency); the aliases track the latest of each family. Container federations instead route per confidence tier via the native backend's `llm.tier.<tier>.model`.

**Effort-level routing (host-run, [#1444](https://github.com/Replikanti/agentis-colonies/issues/1444)).** Both host-run scripts also pass an explicit `claude --settings '{"effortLevel":"<value>"}'` alongside `--model`, so a session's reasoning effort is a FIXED script default instead of inheriting the operator's account-level `effortLevel` from `~/.claude/settings.json` — on a host where the operator maintains a high personal default (e.g. `xhigh`), every one of the federation's daemons would otherwise burn maximum-effort chain-of-thought on routine, low-complexity prompts (typed-JSON extraction, binary discipline, pattern summary) for no quality gain. `tools/flat-cyborg-claude.sh` (reasoning sessions) defaults `CLAUDE_REASONING_EFFORT` to **`medium`** — empirically validated as the sweet spot across the federation's three prompt classes. `tools/code-edit-in-checkout.sh` (code-generation sessions, all three `claude --model "${CODE_EDIT_MODEL:-opus}"` invocation sites: the `--decompose` step, the one-attempt path, and the multi-attempt continue-on-incomplete loop) defaults `CODE_EDIT_EFFORT` to **`high`** — code generation is the federation's heaviest workload and warrants stronger reasoning than the lighter `prompt()` reasoning path. Both knobs accept `low|medium|high|xhigh`; an unrecognised value falls back to the script's default with a `stderr` warning rather than reaching `claude --settings` unvalidated (a malformed JSON value could make the CLI reject the invocation outright). Both default in-script — same env-passthrough posture as `CLAUDE_REASONING_MODEL`/`CODE_EDIT_MODEL`: an operator override exported before the daemon starts reaches the script's shell environment the same way those already do, so no NEW `exec.env_passthrough` allowlist entry is required. Env-only (no `colony.toml` schema change); no per-tick or per-agent override, script-level default only.

**Federation-wide LLM-session concurrency cap ([#1352](https://github.com/Replikanti/agentis-colonies/issues/1352)).** Running many agents at the autonomous tier makes every agent `prompt()` each tick, each spawning a `flat-cyborg` → Claude-Code PTY session; on a single host these thrash and wedge (watchdog-restart pileups, hung sessions). **Lowering confidence does NOT help — a dormant agent still `prompt()`s each tick.** The [#1367](https://github.com/Replikanti/agentis-colonies/issues/1367) `CODE_EDIT_MAX_CONCURRENT` semaphore caps code-edit *orchestrators* only, not the reasoning sessions. `tools/lib/llm-session-slot.sh` adds the missing **global** cap: a `mkdir`-based counting semaphore over `K = ${LLM_MAX_CONCURRENT:-3}` slot dirs (portable — `mkdir` is atomic on Linux + macOS, deliberately NOT `flock(1)` which stock macOS lacks; slot dir resolved in `_llm_slots_dir()`: the `AGENTIS_LLM_SLOTS_DIR` override — honoured on DIRECT invocations only, because agentis-core **force-strips the entire `AGENTIS_*` namespace from daemon children regardless of the `exec.env_passthrough` allowlist** (proven empirically in the [#1426](https://github.com/Replikanti/agentis-colonies/pull/1426) QA) — then the production path: the fed-fixed pool **derived from the allowlisted `COLONY_DIR`** (`<COLONY_DIR>/../.agentis/llm-slots`), which every reasoning and editing child receives). Both `flat-cyborg-claude.sh` (reasoning) and `code-edit-in-checkout.sh` (editing) `acquire_llm_slot` before spawning flat-cyborg and release after, so the cap covers the **total** session count. A slot leaked by a SIGKILL'd session self-heals via a PID-liveness reclaim (mirrors the daemon-registry idiom). Under contention an agent waits its turn (bounded by `${LLM_SLOT_WAIT_S:-120}`, then **fails open** — a prompt is only ever delayed, never dropped) — backpressure, not a new failure mode. Tune `K` per host capability.

A colony's `[llm] backend` in `colony.example.toml` is `"cli"` — meaning "use the agentis daemon default", which **inherits** the federation-level backend from `.agentis/config`. **Do not hardcode `"flat-cyborg"` there**: it would override the federation default and break the host wrapper path. The federation default (orchestrator hermetic config, or `install.sh`-written `.agentis/config`) is the single source of truth.

**Adversarial second-opinion backend (code-review `qa_reviewer`, [#1405](https://github.com/Replikanti/agentis-colonies/issues/1405), step 2 of [#1359](https://github.com/Replikanti/agentis-colonies/issues/1359)).** `qa_reviewer` judges each open MR on a third verdict dimension beyond completeness and description-vs-diff: **`adversarial`** — an independent, default-skeptical second opinion prompted to actively *refute* the change (hunt for one concrete input/state/sequence where it is wrong, incomplete, or breaks an adjacent consumer), never to summarize. A concrete refutation is `adversarial=fail` with a one-line reason; the structured note becomes `QA verdict: completeness=…, description-vs-diff=…, adversarial=pass|fail`. **Cross-provider optional:** when the operator sets `QA_ADVERSARIAL_LLM_CMD` to an alternative `llm.command` backend, the refutation prompt is piped through *that* command (prompt on stdin, reply on stdout — the same contract `flat-cyborg-claude.sh` honours) so the second opinion can come from an independent model; absent the env var it falls back to the colony's default backend via `prompt()`. The env var only **reroutes** the dimension — its absence never disables it, and the dimension is always computed. **`getenv()` reads the SANITIZED env** — the daemon strips every var not on the `exec.env_passthrough` allowlist before the `.ag` runtime sees it (`/proc/<pid>/environ` still shows the full exec-time env, which makes the gap invisible to inspection — proven live on the #1424 burn-in, where `AG_DRIVEN_EDIT_LOOP=1` was in the daemon env yet `getenv()` returned `""`). `install.sh` registers `QA_ADVERSARIAL_LLM_CMD` on the allowlist since the [#1428](https://github.com/Replikanti/agentis-colonies/issues/1428) audit (as it already did the triage `ROUTER_RULE_FIRST` / `LABELER_RULE_FIRST` knobs), so on an up-to-date install the operator export takes effect; on a hand-customized allowlist the install.sh residue check (#1437) names anything missing, and the `check-getenv-allowlist.sh` colony-lint check enforces registration for every future getenv-read knob. Gating approval/merge on the QA verdict remains **out of scope** here (step 3 follow-up of #1359); `review:qa_verdict` stays an extension point.

Caveat: the host-run `flat-cyborg-claude.sh` wrapper (`dev-apprenticeship`, `dark-factory`) now reads the model's reply from a **result file claude writes** with its file-write tool ([#1219](https://github.com/Replikanti/agentis-colonies/issues/1219)), so reply fidelity no longer tracks the TUI layout; the `--extract` screen-scrape is only a **fallback** for when claude does not write the file. Container federations that use the **native** `flat-cyborg` backend with `--extract` still screen-scrape, so keeping a metered `claude`/`openai` fallback available there remains sensible. Deployment prereq: a `flat-cyborg` >= 0.9.0 binary with `--no-jitter` on PATH plus a logged-in `~/.claude`.

**Screen-scrape-only opt-out for weak models (`FLAT_CYBORG_RESULT_FILE`, [#1449](https://github.com/Replikanti/agentis-colonies/issues/1449)).** The result-file channel above assumes the invoked model reliably drives its own file-write tool; that assumption held for the sonnet/opus tiers `flat-cyborg-claude.sh` routes to, but broke for a WEAK model (haiku) live-diagnosed on this federation: haiku's file-write tool call against the `$RESULT_FILE` path silently no-ops — the file stays 0 bytes — while the `[OUTPUT CHANNEL]` directive text is still sitting on the TUI, which then also confuses `--extract-structural`'s chrome-scrape fallback (it recovers directive prose instead of the actual reply, or nothing at all), producing empty/garbage replies the caller fails to decode. `FLAT_CYBORG_RESULT_FILE` (default `1`/on) opts a given invocation OUT of the whole result-file apparatus: set `FLAT_CYBORG_RESULT_FILE=0` and the wrapper (a) never appends the `[OUTPUT CHANNEL]` directive to the prompt, and (b) invokes flat-cyborg with plain `--extract` only, dropping `--extract-structural` — the plain sentinel-first screen-scrape path, which is what was empirically proven reliable for haiku. Live validation covered all three federation prompt classes exercised by `flat-cyborg-claude.sh`: a bare short reply (`"yes"`), multi-line typed JSON (via the [#1445](https://github.com/Replikanti/agentis-colonies/issues/1445) plain-text sentinel unwrap), and a logic-bug prose summary — haiku returned clean, decodable replies on the sentinel-only path across all three. **Honest caveat: this is a SHORT-REPLY, weak-model opt-out, not a general replacement for the result-file channel** — screen-scrape-only reintroduces the pre-#1219 scroll limitation (a reply taller than the terminal screen scrolls the sentinel out of view before `--extract` can read it), so it is unsuitable for the federation's long code-generation or multi-paragraph-analysis prompts; those should stay on the result-file default (`FLAT_CYBORG_RESULT_FILE` unset, or explicitly `1`). No auto-detection from `CLAUDE_REASONING_MODEL` is implemented — the knob is an explicit opt-in the operator sets per deployment, not a maintained "weak model" allowlist.

**Per-agent reasoning-model routing (#1451).** The two knobs above (`CLAUDE_REASONING_MODEL`, `FLAT_CYBORG_RESULT_FILE`) are wired **per agent** in `dev-apprenticeship`'s `start-colony.sh` scripts so the federation actually realizes the ~3× haiku cost saving instead of running every daemon on the sonnet default. A `reasoning_route_for()` helper — mirroring the existing `tick_interval_for()` per-agent case pattern — echoes `"<model> <result_file>"`; both launch sites in each script (the main `AGENTS` loop AND the `--restart-agent` single-daemon respawn path) split it with the bash-3.2-safe `${route% *}` / `${route#* }` expansions and prefix the launch with `CLAUDE_REASONING_MODEL="$m" FLAT_CYBORG_RESULT_FILE="$rf" agentis daemon …`. **Mechanism:** this needs NO `exec.env_passthrough` allowlist entry — `flat-cyborg-claude.sh` is the `llm.command` the daemon spawns as a direct subprocess, so it inherits the daemon's process env and reads both vars via `${VAR:-default}` (the same path #1444/#1449 already ship; this issue only varies the values per agent). **Five agents route to `haiku` + `FLAT_CYBORG_RESULT_FILE=0`** — the bounded typed-JSON-extract / binary-gate classes proven 8/9 on haiku in #1450: triage `router` (`RoutingAnalysis`+`RouteAction`), `labeler` (`LabelAnalysis`+`LabelAction`, the proven case), `prioritizer` (`PriorityAnalysis`+`PriorityAction`); planning `scope_estimator` (`CalibrationSummary`+`ScopeEstimate`); release `ship_decider` (`ShipPatterns`+`ShipDecision`, the binary ship-gate). Everyone else stays on `sonnet` + the default result-file channel (`FLAT_CYBORG_RESULT_FILE=1`), byte-identical to pre-#1451. **The constraint that decides membership:** `FLAT_CYBORG_RESULT_FILE` is a per-**daemon** env var — it cannot be split per-`prompt()` — and haiku requires screen-scrape (`=0`, since it silently no-ops the result-file write), which reintroduces the pre-#1219 scroll limit, so an agent qualifies for haiku **only if every one of its `prompt()` replies is a bounded fixed-field struct**; one long-reply prompt in the daemon disqualifies the whole agent. **Honest exclusions:** `changelog_writer` — the issue named its ship-gate for haiku, but the *same daemon* also runs the `ChangelogDraft` prompt whose `changelog` field is unbounded markdown release notes (scrolls), so the whole agent stays on sonnet and that ship-gate saving is deliberately forgone; `version_bumper` — replies are short (`VersionBump`) but it is a **terminal writer** (creates the release/tag at the autonomous tier) and tier policy keeps terminal writers on the stronger model; `logic_reviewer` (and the other `*Review` reviewers) — long analytical replies, and `logic_reviewer` is haiku's weakest class (2/3 on pattern-summary). Edge-case safety: if a "short-reply" agent ever overflows the screen, screen-scrape drops the sentinel and the typed decode fails → agentis retries (total-on-failure, no silent corruption), and an operator reverts one agent by editing the single case line. Source-pinned by `tools/test-start-colony-model-routing.sh` (recording-shim over the `--restart-agent` path). The `implementation` and `code-review` colonies have zero haiku agents and stay byte-identical; code generation (`code-edit-in-checkout.sh`, opus) is untouched.

macOS Keychain caveat ([#1343](https://github.com/Replikanti/agentis-colonies/issues/1343)): the **editing** claude session that `tools/code-edit-in-checkout.sh` spawns from `code_writer`'s detached job is a grandchild across the agentis `exec` boundary, which sanitizes the env (`USER`/`LOGNAME` unset) and drops the GUI security session. macOS Claude Code reads credentials from the **login Keychain**, which is unreachable from that context, so the session comes up **"Not logged in"** and makes zero edits (the reasoning/draft session — a direct daemon child — is unaffected; `setsid`/`setpgrp`/`launchctl asuser` detach variants all failed to restore Keychain access). Sidestep it with an opt-in file credential: `code-edit-in-checkout.sh` reads a long-lived token from `CLAUDE_OAUTH_TOKEN_FILE` (default `<fed>/.agentis/secrets/claude-oauth-token`, already covered by the `.agentis/` gitignore rule) and exports it as `CLAUDE_CODE_OAUTH_TOKEN` before spawning flat-cyborg, but never clobbers a `CLAUDE_CODE_OAUTH_TOKEN` already in the env. **The token MUST come from `claude setup-token`** (long-lived, headless) — a raw OAuth `accessToken` copied out of a Linux `~/.claude/.credentials.json` is the WRONG token type for that env var and yields **401 Invalid authentication credentials**. `dev-apprenticeship/install.sh` §6 prompts macOS operators to provision this token during setup (no-op on Linux). Absent the file the behaviour is unchanged, so Linux hosts (whose daemon-child session reaches credentials normally) need nothing.
